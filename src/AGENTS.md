# Office CLI

- Terminal progress: use `src/report/` for live output and Clack for prompts and permanent messages. Keep unchanged labels and headings on screen; animate only the glyph and clock. Batch log bursts and repo updates into frames, retain recent output for failures, and fit live rows by terminal columns. When changing the renderer or upgrading Clack, run `bun test ./src/report/clack.test.ts` from the repo root and capture the affected path in a pseudo-terminal: an idle label should be written once and a log burst should leave its heading untouched.
- The installed executable has no adjacent checkout, Node or npm. Access bundled files through `tool.ts`; keep the installed and checkout forms of a built-in package equivalent.
- Keep one `office.yaml` schema (`schema.ts`) and one source for injected office guidance (`packages/office/plugin/instructions.ts`); both the CLI and the required package consume them. Validate external data at the boundary with `check(v.safeParse(...))`. New runtime dependencies require user agreement and an exact pin; code shared with the plugin affects its bundle too.
- Treat `.office/` as tool-managed and root-level files as the owner's; `machine.packages.toml` is shared: sync owns its tool list and comments, the office its versions. Sync reconciles which tools packages supply, preserving the office's versions unless one is below a package's declared version; other upgrades are explicit. Apply the same upgrade gate to an existing package service definition as to an existing runtime pin.
- Machine-wide mise fragments take effect only through global links; a project's `mise.toml` still wins in its folder. Install global tools from `/`. Resolve fragment hooks relative to `config_source` because the caller can be anywhere. Don't set `MISE_GLOBAL_CONFIG_FILE` in the agent environment: it disables global conf.d.
- Only one consenting host office manages a machine. Write whole, office-named files outside the office and its state, replace or remove only recorded paths, and leave them across `office down`. Release them when the office relinquishes management. Keep per-machine desktop panel installation separate: last sync wins and panels are not automatically removed.
- Resolve OpenCode addresses and session folders from `office.opencode`; generated Executor apps need the same view as the CLI. Type-check apps against the version the connected Executor actually reports.
- Raise starting pins and tested ranges together after verification. Never downgrade OpenCode or Executor data. Keep release discovery usable without GitHub credentials and on the office's release line. Respect minimum ages: three days for packages and built-in package tool defaults, at least a day for tools generally. Browse is the deliberate exception.
- Package command output: a reader sends descriptor 1 (and Bun's copy of it) to standard error before it gathers, so package code and the processes it starts can't reach standard output (`src/command-stdout.ts`). A `result` handler's text goes through a pipe on the reader's descriptor 4, which the first process reads while the reader runs and prints only when it exits 0; `run` and help get standard output back after gathering. Don't print a command's data any other way, and don't intercept `console` or `process.stdout` instead.
