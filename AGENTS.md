# opencode-office

The `office` tool: the CLI (`src/`, run from a checkout by `bin/office`), the two plugins every office runs (`plugins/`), the template `office init` copies (`template/`), the base image of the `opencode` container (`image/`) and the compose file for `executor` and `opencode`. `README.md` describes the layout, runtime and commands. Offices are separate repositories, each owning its content (desks, skills, apps, services); that content changes in the office, not here.

- `office` ships as one executable people drop on their PATH, with no Node, npm or checkout beside it. Reach the tool's own files only through `src/tool.ts`, which finds them embedded in the executable or in the checkout; a new folder the CLI reads at run time joins its `assets` list.
- The template is copy-once: `office init` copies it and the office owns the copy, so a template change reaches an existing office only when someone copies it there; when an office you work with should get it too, say so. The plugins are the tool's: `office sync` replaces each office's copies, so change them only in `plugins/`, then run `office sync` in each office you use and commit its copies there.
- `plugins/office/instructions.ts` is the one source of the guidance the office plugin injects; `office instructions` runs the same file, bundled into the executable.
- The CLI is TypeScript on Bun (Bun APIs are fine; it never runs on Node), with pnpm for packages. Keep runtime dependencies to `yaml`. Check with `pnpm run typecheck`.
- Agents are deliberately unrestricted; the container is the boundary (in host mode, the host server's own configuration is). Add permission rules only when the user asks.
- Only OpenCode has a mode (`opencode:` in `office.yaml`): its container, or a server already running on the host that the office never starts or stops. Executor and an office's own services always run in containers. Take OpenCode's address and the session folder from `office.opencode` (`src/office.ts`); Executor apps get them from `office.ts`, which `office apps deploy` generates per mode.
- The `opencode` container holds only its own Executor token; every service credential lives in Executor.
- Keep every published port on `127.0.0.1`.
- Pins are exact: images by tag and digest; OpenCode, Claude Code, mise and supercronic by version and SHA-256 in `image/Dockerfile`; Bun and pnpm in `mise.toml`. Raise `OPENCODE_VERSION` only: newer versions migrate the sessions database in the home volume. Packages must be at least three days old (`pnpm-workspace.yaml`), tools at least a day.
- Cron job scripts in an office stay plain shell that knows nothing of the runner. Container mode wraps them for supercronic with stamps and catch-up (`src/cron/container.ts`); host mode generates systemd user timers with `Persistent=true` (`src/cron/host.ts`).
- Version cutoffs come from mise itself (`mise latest --minimum-release-age 1d`), not from release dates the tool works out on its own.
- Executor app sources in the template must type-check against the `apps` version Executor reports (`office apps deploy` refuses a mismatch): `bun add --no-save apps@<version>` beside the app, then `bunx -p typescript@7.0.2 tsc --ignoreConfig --noEmit --strict --skipLibCheck --module nodenext --moduleResolution nodenext --target es2022 index.ts`.
- This repository is public: commit nothing personal or machine-specific (home paths, emails, IDs, credentials). The gitleaks pre-commit hook (`pre-commit install`) and the workflow's gitleaks job catch secrets.
- Every push to `main` publishes a pre-release through `.github/workflows/release.yml`, built with `pnpm run build --prerelease <UTC datetime>`. In workflows, pin each action to a full commit SHA with its version in a comment, keep `permissions` minimal per job, and check changes with `actionlint` and `zizmor --min-severity high`.
- Verify a change with `pnpm run install-office`, then `office init` in a scratch folder outside this repository followed by `office check`, and `office check` in an office that is running (it compares the host's and the container's `office --version`; rebuild that office's image with `office up` after changing `image/` or the CLI). Prove host-mode changes in a scratch office against a host OpenCode server, on other ports (`EXECUTOR_PORT=42440`) with `state:` inside the scratch folder, so they never touch a running office.
